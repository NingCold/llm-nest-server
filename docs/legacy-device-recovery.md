# 升级真人设备与恢复文件

升级到设备准入协议后，原 v1 密文和会话备份继续按原版本保留，旧备份不再接收新会话。先备份 PostgreSQL；升级前后的客户端与服务器按同一候选版本一起切换。

**只读历史。** 已登录的本人可以在 Web「可信设备与恢复」创建或解锁本机库，选择「从恢复文件导出历史正文」，并选原 v1 文件。读取器只使用此文件对应的云端备份；导出的 JSON 仅含能验证的历史正文，无法解密或验证的记录单列，不含草稿、附件内容或恢复秘密。它不赋予新设备准入权。

**继续聊天或备份。** 对升级前已有的加密账号，服务端预留一次人工登记。本人在原可信设备上用原口令解锁，或在确实失机时创建新的本机库，打开「查看完整设备指纹」。实例运维人员通过升级前已建立的独立身份渠道核验本人，并当面或通过该渠道比对账号 UUID、设备 ID 和 Ed25519 公钥指纹。普通账号登录、恢复文件、邮件中的自述或单方提供的截图都不能替代核验；若没有独立依据，保留历史读取，不登记新设备。

在既有受限运维终端选择该实例的 PostgreSQL 连接，使用已配置的数据库管理身份运行（占位符仅为公开标识）：

```sh
psql -X -v account='账号UUID' -v device='设备UUID' -v fingerprint='已核对的Ed25519公钥' -f scripts/enroll-legacy-device.sql
```

成功只登记指定设备一次；已撤销、指纹不符、已登记或新建的账号不会获得这项迁移资格。保留操作时间、核验渠道和所选公开指纹的受限运维记录，不收集本机口令、种子或文件。本人在设备上检查更新；新库再次导入原文件，导入既有历史。用这台设备生成、下载并确认新的 v2 恢复文件，才启用未来备份。之后换机由现有可信设备或当前 v2 文件授权，不再运行迁移脚本。

日常撤销请用另一台可信设备。撤销提交后，旧文件仍可读其历史，但不再批准新设备。撤销方应立即保存并确认新的 v2 文件，其他健康端用该文件或可信设备授权同步新备份钥。若本机没有原备份钥，仍可创建新一代；封存的旧备份只用匹配的旧文件读取。保留旧文件，它可能是读取更早归档的唯一途径。若历史转换跨越两代，在验读时先选开始转换时的原文件，再补选当前 v2 文件。
